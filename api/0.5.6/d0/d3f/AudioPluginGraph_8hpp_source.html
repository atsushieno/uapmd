16 // AudioPluginGraph is supposed to abstract away how it internally routes audio plugin instances.
17 // It is supposed to `process()` audio and UMP inputs. In that sense, it is a track on a DAW alike.
18 //
19 // It can process nodes in a simple linear way. As a minimum requirement, it must support
20 // a linear chain of nodes, by "add" and "remove" functions.
21 // Advanced DAG topology editing lives in AudioPluginFullDAGraph.
22 //
23 // Note that it is NOT to represent an entire audio graph that is supposed to involve audio device nodes.
24 // That should be handled by a sequencer, which is out of the scope of this class (not even of this library).
25 //
26 // Usually an audio plugin instance shares its lifetime with `AudioPluginNode` when it is being added to the graph,
27 // but the instance is "owned" by the `AudioPluginHostingAPI` implementation.
28 // `appendNodeSimple()` takes a delegate function called when the instance is being removed by `removeNodeSimple()`
29 // or whatever that removes `AudioPluginNode`, to help this mechanism.
